   - `juice_shop`: OWASP Juice Shop target (IP: 172.28.0.5).
   - `kali_attacker`: Kali Linux container (IP: 172.28.0.10).

   - Pre-packaged Kali Linux rolling container with `nmap`, `hydra`, `metasploit-framework`, `hping3`, `curl`, `net-tools`.

Verification Completed:
- Tested ping & HTTP reachability from Kali to Juice Shop.

PHASE 2 — Real Packet Capture + Feature Extraction
-------------------------------------------------------------------------------
Problem Solved:
- Replaced fake simulated socket state checks (`psutil.net_connections`) with real raw packet capture and sliding-window feature aggregation.

What We Added:
1. `backend/pipeline/feature_extractor.py`:
   - 5-second sliding window per source IP.
   - Computes packet statistics: `syn_count`, `ack_count`, `rst_count`, `unique_dst_ports`, `bytes_sent`, `connection_frequency`, `failed_auth_count`.
2. `backend/watchers/network_watcher.py`:
   - Upgraded to Scapy `AsyncSniffer` capturing live IP packets directly on `phantom-lab` network interface (`br-*`).
   - Parses TCP/UDP headers and HTTP payloads.
3. System Dependencies & Host Setup:
   - Added `scapy==2.7.0` to `backend/requirements.txt`.
   - Installed `libpcap-dev` for native BPF packet filtering.
4. `backend/test_phase2.py`:
   - Verification test script.

Verification Completed:
- Ran live Nmap scan from `kali_attacker` container -> Scapy captured real packets -> `FeatureExtractor` computed exact metrics (`unique_dst_ports: 10`, `syn_count: 10`, `bytes_sent: 580`).

PHASE 4 — LLM "Brain" Integration (Gemma 4 E4B via Ollama)
-------------------------------------------------------------------------------
Problem Solved:
- Needed a reasoning LLM engine ("The Brain") to consume live traffic feature statistics and GNN structural anomaly scores to produce structured threat verdicts and mitigation commands.

What We Added:
1. `backend/pipeline/gemma_engine.py`:
   - Refactored prompt template to accept feature stats and GNN anomaly scores.
   - Integrated Ollama API targeting `gemma4:e4b` (`http://localhost:11434/api/generate`).
   - Enforced strict JSON verdict schema: `threat_type`, `confidence`, `severity`, `attack_pattern`, `action`, `explanation`, `reason`, `indicators`, `mitigation`.
   - Added robust rule-based fallback for offline resilience.
2. `backend/test_phase4.py`:
   - Verification test script testing Benign, PortScan, and Zero-Day feature vectors.

Verification Completed:
- Verified JSON response formatting and schema compliance.
- Benign Sample -> `BENIGN` (Severity 2, LOG, Mitigation: NONE)
- PortScan Sample -> `PORT_SCAN` (Severity 7, CONTAIN, Mitigation: iptables DROP rule)
- Zero-Day Sample -> `UNKNOWN_ZERO_DAY` (Severity 8, CONTAIN, GNN score 0.8920)
