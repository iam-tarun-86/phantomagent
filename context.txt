PHASE 9 — 2026 SOTA Multi-Signal Consensus & Zero False Positive Pipeline
-------------------------------------------------------------------------------
Goal:
- Upgrade PhantomAgent from GNN-only detection to 2026 State-of-the-Art (SOTA) Multi-Signal
  Evidence Consensus architecture to eliminate false positives and alert fatigue.

What We Added:
1. backend/pipeline/entropy_analyzer.py (Shannon Payload Entropy):
   - Computes byte-level Shannon entropy H(X) = -sum(p * log2(p)) in [0.0, 8.0] bits/byte.
   - Detects encrypted C2, DNS exfil, ransomware headers (H > 7.2) and low-entropy exploit pads (H < 2.0).

2. backend/pipeline/behavioral_fingerprint.py (Per-IP Rolling Z-Score Outlier Engine):
   - Maintains rolling mean (mu) and std dev (sigma) per source IP across packet count,
     unique destination ports, connection frequency, and SYN rates.
   - Z = (X - mu) / sigma. High-activity hosts (e.g. backup servers) accumulate high baselines,
     preventing false alerts (Z <= 2.0). Unseen IPs bursting activity trigger Z > 3.0 sigma.

3. backend/pipeline/killchain_correlator.py (MITRE ATT&CK Temporal Campaign Tracker):
   - Tracks per-IP progression across MITRE ATT&CK kill-chain stages (Recon -> Access -> Execution -> Exfil).
   - Flag multi-step APT campaigns when an IP advances through >= 2 distinct stages in 1 hour.

4. backend/pipeline/conformal_predictor.py (Statistical FPR Bounding):
   - Calculates empirical p-values against benign calibration distributions.
   - Bounds False Positive Rate (FPR) statistically to <= 5% (alpha = 0.05).

5. backend/pipeline/consensus_gate.py (5-Signal Ensemble Gate):
   - Integrates 5 independent detectors: GNN Anomaly Score, Conformal P-Value, Behavioral Z-Score,
     Payload Shannon Entropy, and MITRE ATT&CK Kill-Chain progress.
   - Enforces N-of-5 ensemble rule: Requires >= 3 positive votes to confirm threats.
   - Suppresses single-anomaly noise to prevent alert fatigue.

6. backend/pipeline/decision_engine.py & backend/main.py:
   - Integrated ConsensusGate into full pipeline flow.
   - Broadcast consensus votes and status over WebSocket telemetry.

PHASE 13 — Port Scan Misclassification Fix & Gemma LLM Inference Integration
-------------------------------------------------------------------------------
Problems Solved:
1. Issue 1: Port Scan was being misclassified as DoS Attack.
   Root Cause: In `network_watcher.py`, `is_dos` check was placed before `is_scan` and flagged `DOS_ATTACK` whenever `packet_count >= 30` without checking `unique_dst_ports <= 2`. An Nmap scan probing 30 ports (`unique_dst_ports = 30`, `packet_count = 30`) was hitting `is_dos` first!
   Fix: Port scan signature (`unique_dst_ports >= 3`) is now checked FIRST in `network_watcher.py`. `is_dos` is strictly restricted to high volume floods targeting 1-2 ports ONLY (`unique_dst_ports <= 2`).

2. Issue 2: Gemma LLM was falling back to rule-based analysis and not receiving inputs.
   Root Cause:
   a) `gemma_engine.py` health check sent GET requests to `/health` or OPTIONS on `/v1/chat/completions`, which `llama.cpp` on port 8085 rejected with 404, setting `is_available = False` permanently at startup.
   b) `GEMMA_TIMEOUT` was 30s, causing Gemma 4 chain-of-thought generation to time out.
   c) `max_tokens` was set to 512, truncating the JSON output mid-response and throwing a JSONDecodeError.
   Fix:
   a) `gemma_engine.py` now queries `/v1/models` (official OpenAI models endpoint supported by `llama.cpp`).
   b) Added automatic reconnect retry on inference if initial startup check failed.
   c) Raised `GEMMA_TIMEOUT` from 30s to 60s in `config.py`.
   d) Raised `max_tokens` to 1024, instructed concise output without thinking blocks, and added truncated JSON string recovery.

Verification Completed:
- Tested Gemma LLM connection live: `Is available: True`, `source: "GEMMA_LLM"`.
- Verified live inference output returning structured JSON verdict for `PORT_SCAN`.

PHASE 22 — Real Graph Neural Network: Message Passing Over Host Graphs
-------------------------------------------------------------------------------
Problem Solved:
*** THE GNN WAS NOT A GNN. *** `adj_matrix` was never passed — not in training, not at
inference. The message-passing branch in forward() was DEAD CODE. The model advertised
as GraphSAGE was, in every executing path, a 4-layer MLP on 7 scalar features.
Also: nothing in this project was ever CICIDS2017. `cicids2017_subset.csv` was generated
by 41 np.random calls in generate_dataset.py.

What We Added:
1. `FeatureExtractor.get_graph_snapshot()` — builds the window's communication graph.
   Nodes = IPs, edges = "A sent packets to B". The per-IP deques already held both
   endpoints; nothing new is captured.
2. Real GraphSAGE aggregation: the layer sees [self_embedding ; mean(neighbours)] rather
   than the neighbour mean alone, so isolated benign hosts still score correctly.
   Checkpoint v3 (sage layer input is 2*hidden — v2 weights are incompatible).
3. `predict_graph_scores(snapshot)` scores a whole window in one pass.
   `predict_anomaly_score(features)` unchanged for single-host callers.
4. Dataset rebuilt as GRAPH WINDOWS and renamed honestly:
     backend/data/synthetic_graphs.jsonl   (2300 windows, 22k nodes, 16.7k edges)
     backend/data/synthetic_flows.csv      (flat table, for the behavioural baseline)
     backend/models/gnn_phantom.pt
   CICIDS2017 claim removed from the LLM system prompt and GNNPanel.jsx.
5. CRITICAL DESIGN POINT: a benign "multi-service client" archetype whose scalar
   features are IDENTICAL to a port scanner's BY CONSTRUCTION. The first attempt kept
   them separable and the model learned the features and ignored topology entirely —
   zero-day recall collapsed to 0.9%. They are now separated only by neighbourhood: a
   scanner's targets answer with RSTs, a monitoring agent's do not.
6. `backend/scripts/ablation.py` — three ablations, reproducible.
7. `scripts/demo_judges.sh` — four narrated acts + `--check` preflight that verifies
   venv, torch, all three model artefacts, docker, sudo, containers, backend
   reachability and stale PHANTOM rules. Exits non-zero on anything that would break a
   live presentation. Mutates nothing in --check mode.

*** CORRECTION TO PHASE 19 ***
Phase 19 claimed the evidence-source gate rule stopped a single model carrying a verdict.
Enumerating ALL 32 vote combinations disproved this:
  - The old flat 3-of-5 rule ALREADY rejected gnn+conformal alone. Both rules reject it.
  - One corroborating signal sufficed under BOTH rules. Unchanged.
  - The new rule is MORE PERMISSIVE: 25 of 32 combinations pass, vs 16 under flat.
It is a CORRECTNESS fix (correlated evidence no longer double-counted), NOT a
false-positive reduction. Docstring corrected; ablation 3 prints the comparison.
Threshold stays at 2 deliberately — raising it to 3 tightens to 13 combinations but
suppresses single-window port scans (which produce only structural + behavioural).
